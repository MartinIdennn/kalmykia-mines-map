# Команда агентов — правила оркестрации

В этом проекте ведущий агент (основная сессия) работает как **оркестратор** команды сабагентов.
Прямого общения между сабагентами нет — координация идёт через оркестратора и общий файл `CHECKLIST.md`.

## Команда

| Агент | Роль |
|---|---|
| `implementer` | пишет/меняет код по пункту чек-листа |
| `tester` | запускает тесты/линт, возвращает фактический результат |
| `reviewer` | принимает пункт, выносит вердикт done/failed |
| `skill-builder` | создаёт новые скиллы в `.claude/skills/` |
| `agent-smith` | создаёт новых сабагентов в `.claude/agents/` |

## Цикл оркестрации (пока чек-лист не закрыт)

1. **План.** Разбей задачу на атомарные пункты, запиши их в `CHECKLIST.md` (раздел «Пункты»), статус `[ ]`.
2. **Делегирование.** Для каждого открытого пункта поставь статус `[~]` и вызови подходящего агента.
   Независимые пункты делегируй параллельно (несколько Agent в одном сообщении).
3. **Приёмка.** Прогони результат через `tester`, затем `reviewer`.
   - вердикт `done` → статус `[x]`, запись в «Журнал»;
   - вердикт `failed` → статус `[ ]` (или `[!]`, если блокер), с заметкой что доделать.
4. **Новые потребности.** Не хватает процедуры → `skill-builder`. Не хватает роли → `agent-smith`.
   Новые пункты добавляй в чек-лист.
5. **Повтор** с шага 2, пока все пункты не `[x]` (или явно не `[!]` с объяснением).
6. **Финал.** Когда все галочки проставлены — короткий итог: что сделано, что заблокировано и почему.

## Принципы
- `CHECKLIST.md` — единственный источник правды о прогрессе. Держи его в актуальном состоянии.
- Сабагент закрывает пункт не сам — только оркестратор после проверки.
- Отчёты тестов приводи честно: упало — показывай вывод, тестов нет — так и говори.

## Автономный режим
Для запуска без пошагового участия есть workflow `.claude/workflows/agent-team.js`
(план → реализация → тесты+ревью, цикл до закрытия). Запускается отдельно по согласию пользователя.
